## 数据模型复用结论

现有 `accounts`、`categories`、`ledger_transactions` 三张 Drift 表已经包含本轮需要的账户、分类、整数金额、交易日期、备注、创建/更新时间和软删除字段。本次没有新增、删除或改变 SQLite 列：

- `schemaVersion` 保持为 `1`。
- 不需要 migration，也没有清空或重建用户数据库。
- `amount_minor` 继续使用整数最小货币单位；界面字符串通过确定性解析转换为整数分。
- 为 `account_id` 和 `target_account_id` 补充了不同的 Drift `@ReferenceName`，只修复生成器反向关系命名冲突，不改变数据库 schema。

## 已知风险与下一步

- 数据库列目前没有金额非负、交易类型枚举等 SQLite `CHECK` 约束，主要依靠 Repository 校验。若以后补充约束，必须升级 schemaVersion、实现保留数据的 migration，并增加 v1 旧库升级测试。
- 当前月份在 Provider 创建时取值。App 跨月持续不重启时，统计周期不会自动切换；下一步可增加日期时钟 Provider 或生命周期刷新。
- 模拟器系统日期比当前日期慢一天，日期边界验收前应同步时间。
- 下一步优先补账户/分类管理、余额计算，以及 `transfer`、`refund` 的确定性规则和迁移设计。
